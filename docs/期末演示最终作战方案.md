# SmartRead Agent 期末演示最终作战方案

## 1. 当前阶段判断

SmartRead Agent 已进入软件开发实践（三）期末演示准备阶段。当前不再继续增加 App 大功能，项目重点从“开发功能”转为“现场高分表达”和“详细设计说明书提交”。

软件开发实践（三）的现场演示重点应放在：

1. App 应用创新和实用性。
2. 移动应用功能丰富度。
3. 机器学习在应用中的整合程度。
4. 团队协作和精神面貌。
5. PPT 效果与时间控制。

其中“机器学习在应用中的整合程度”是最重要得分点，现场必须重点讲清 LiteRT 端侧句子重要性分析，而不是过多展开项目管理材料。

软件项目管理相关材料只在现场演示中作为“团队协作和迭代过程”的辅助证据简要出现，不作为主线展开。

## 5. 江轩宇固定操作步骤

演示前必须至少彩排两次，操作顺序不要临场改。

1. 打开 SmartRead Agent，停留 2 秒，让老师看到首页和 V1.0 文案。
2. 点击示例文本。
3. 点击“开始智能分析”。
4. 慢慢下滑，展示一句话总结、关键词、分点摘要。
5. 停在 LiteRT 端侧分析区域，让林立洲讲模型输入和端侧推理。
6. 点击 Agent 问答入口。
7. 点击快捷问题“这篇文章主要讲了什么？”或“帮我整理复习重点”。
8. 返回摘要页，进入知识卡片页。
9. 展示知识卡片和复习题。
10. 返回首页，进入历史记录页。
11. 点击一条历史记录恢复分析。
12. 回到首页，准备答辩。

禁止临场粘贴长文本，优先使用内置示例文本。

## 6. Agent 问题统一回答口径

老师在预报告时已经关注过“Agent 是否调用 GPT API”。正式演示中必须提前讲清楚。

### 标准回答

当前版本没有调用 GPT API，也没有依赖云端大模型。项目中的 Agent 是本地规则型阅读 Agent，它基于当前文章的一句话总结、关键词、分点摘要和复习题规则，通过问题意图识别来组织回答。

例如用户问“主要内容”“关键词”“复习重点”“复习题”“知识卡片”时，系统会识别问题类型，并调用本地分析结果生成回答。它不是通用聊天机器人，而是限定在阅读辅助场景中的轻量 Agent。

这样设计的好处是：离线可用、稳定、可解释、现场演示不受网络和 API Key 影响。后续如果继续扩展，可以把云端大模型作为增强能力接入。

### 不能说的话

- 不能说“我们调用 GPT API”。
- 不能说“类似 GPT，所以算大模型”。
- 不能把规则型 Agent 夸大成通用智能体。

## 7. LiteRT 问题统一回答口径

LiteRT 是本项目机器学习整合的重点。

### 标准回答

SmartRead Agent 的 LiteRT 模块用于句子重要性分析。系统先把文章切分为句子，然后为每个句子提取 5 个特征：句子长度、关键词重合度、句子位置、标点提示和总结提示词。模型导出为 `sentence_importance_model.tflite`，放入 Android assets，运行时由 TensorFlow Lite Interpreter 在手机端加载并推理，输出 0 到 1 的重要性分数，再转换成高 / 中 / 低等级展示。

该流程体现了“训练或准备模型 -> 导出 .tflite -> 集成到 Android -> 端侧推理 -> UI 展示”的移动机器学习闭环。

## 8. 现场备用方案

### 真机正常

使用江轩宇手机演示，林立洲同步讲解。

### 真机异常

切换到：

1. Android 模拟器。
2. 已保存的 V1.0 截图。
3. APK 和 GitHub 仓库页面说明。

### 网络异常

项目核心功能离线可用，不依赖网络。仓库页面可以不现场打开，PPT 中保留二维码或链接即可。

### 时间不够

优先展示：

1. 摘要结果。
2. LiteRT 端侧分析。
3. Agent 问答。
4. 历史记录。

知识卡片和复习题可以快速扫过。

## 10. 最终结论

软件开发实践（三）现场演示不要把重点放在 Gitee 统计图、Leangoo 截图和项目管理细节上。这些材料是软件项目管理课程的重点，在本课程演示中只需要用来证明“项目有迭代、有协作、有测试”。

本课程现场最重要的是：

1. App 真能运行。
2. 功能链路完整。
3. LiteRT 端侧模型讲得清楚。
4. Agent 不被误解为 GPT API。
5. 分工自然，演示稳定，时间受控。
