## 二、PPT 逐页讲稿

### 第 1 页 封面

老师、同学们好，我们是 A03 组。我们这次做的项目叫 SmartRead Agent，是一个面向学习文本的 Android 移动端智能阅读助手。我是林立洲，学号 121072021030；组员是江轩宇，学号 121052023075。项目使用 Kotlin 和 Jetpack Compose 开发，并集成了 LiteRT 端侧模型，用来完成句子重要性分析。

今天的汇报主要分成项目背景、功能设计、技术实现、机器学习集成、迭代测试和运行展示几个部分。

### 第 2 页 选题背景

我们选择这个题目，是因为平时看教材、课堂资料或者技术文章时，经常不是读不完，而是读完以后还要再整理摘要、关键词和复习重点。这个过程比较耗时，也容易漏掉关键内容。

所以 SmartRead Agent 的目标不是替代学习，而是帮助用户在手机上更快完成第一遍整理，把长文本先转成比较清楚的摘要、关键词和学习材料。

### 第 3 页 项目定位

这一页说明项目的整体定位。SmartRead Agent 不是单独做一个摘要页面，而是把阅读过程串成一个闭环：先输入或选择文本，再生成摘要和关键词，然后做 LiteRT 端侧句子重要性分析，接着通过 Agent 问答、知识卡片和复习题进行复习，最后可以通过历史记录回看之前的分析结果。

这样的设计更贴近学生实际使用场景，也能体现一个完整移动端应用的基本结构。

### 第 4 页 V1.0 功能总览

当前 V1.0 版本主要包括这些功能：文本输入与示例文本、一句话总结、关键词提取、分点摘要、LiteRT 端侧句子重要性分析、本地规则型 Agent 问答、知识卡片、复习题，以及历史记录保存、恢复和清空。

这些功能不是简单堆在一起，而是围绕“阅读资料到形成复习材料”这个流程组织起来的。

### 第 5 页 核心界面展示

这一页展示 App 的主要页面。首页负责输入文本和启动分析；结果页展示摘要、关键词、分点摘要和 LiteRT 分析；Agent 页面用于围绕当前文章提问；知识卡片和复习题页面用于复习；历史记录页面用于保存和恢复之前的分析。

实际运行效果会在 PPT 结束后通过录屏视频展示，这里先让大家了解页面结构。

### 第 6 页 技术架构

项目技术架构主要分为五层。UI 层使用 Jetpack Compose；文本分析层由 TextAnalyzer 完成分句、摘要、关键词和分点摘要；智能交互层由 LocalReadingAgent 处理本地问答；端侧模型层由 SentenceImportanceClassifier 加载 `.tflite` 模型进行推理；存储层由 HistoryRepository 保存历史记录。

整体思路是尽量把核心流程放在本地完成，保证课堂环境下即使网络不稳定，主要功能也能运行。

### 第 7 页 LiteRT 端侧句子重要性分析

这一页是项目里机器学习集成的重点。我们的 LiteRT 模型用于判断文章中句子的重要性。系统会先把文章切分成句子，再提取长度、关键词重合度、句子位置、标点提示和总结提示词等特征，输入到 `.tflite` 模型中，输出 0 到 1 之间的重要性分数。

App 会把分数转换成高、中、低等级，并显示在结果页中，帮助用户更快看到哪些句子更值得关注。

### 第 8 页 Agent 问答设计

项目中的 Agent 是本地规则型阅读 Agent，不调用 GPT API，也不依赖云端大模型。它的回答来源主要是当前文章的一句话总结、关键词、分点摘要、知识卡片和复习题。

这样做的好处是稳定、离线可用、结果容易解释，也更符合课程项目当前的实现规模。它不是通用聊天机器人，而是围绕当前文章内容提供阅读辅助问答。

### 第 9 页 学习材料生成

在摘要和 LiteRT 分析之后，系统还会继续生成学习材料。知识卡片会把关键词、核心观点和分点摘要整理成卡片；复习题会根据摘要和关键词生成简答题和参考答案；Agent 快捷问题可以帮助用户快速查看文章主旨、关键词和复习重点。

这部分主要体现项目从“分析文章”进一步走向“辅助复习”。

### 第 10 页 数据对象与本地存储

这一页说明主要数据结构。ArticleAnalysis 保存原文、摘要、关键词、分点摘要和 LiteRT 结果；SentenceImportance 保存句子、分数和等级；ChatMessage 保存用户问题和 Agent 回答；KnowledgeCard 和 QuizQuestion 保存复习材料；HistoryRecord 保存历史分析。

历史记录目前使用本地 SharedPreferences 保存，适合 V1.0 课程项目规模。后续如果继续扩展，可以升级为 Room 数据库。

### 第 11 页 工程实现与版本收口

这一页说明工程成果。Android 工程使用 Kotlin 和 Compose，核心入口是 MainActivity。模型文件和 APK 都已经整理到项目目录中，文档材料包括 README、项目说明文档、详细设计说明书、截图和安装说明。

V1.0 版本已经生成课程用 APK，可以安装到安卓手机上运行。源码也同步到 Gitee 和 GitHub，方便复查。

### 第 12 页 迭代过程

项目从最开始的文本输入和摘要 MVP 做起，后面逐步加入 Agent、知识卡片、复习题、LiteRT 模型、历史记录和界面优化。最后进入 V1.0 阶段，主要做 APK、测试、截图、PPT 和详细设计说明书的收口。

这个迭代过程比较符合课程实践要求：不是最后一次性堆出来，而是每个阶段都有可运行成果。

### 第 13 页 小组分工

我们是双人小组。林立洲主要负责整体方案、Android 核心开发、本地摘要、Agent、LiteRT 集成、版本管理、文档和汇报材料。江轩宇主要参与需求反馈、安卓真机安装体验、功能流程复核、UI 使用建议和文档校对。

分工按真实参与情况说明，不刻意夸大某一方的代码贡献。项目材料中也保留了沟通和测试过程。

### 第 14 页 测试与运行结果

测试方面，我们覆盖了 App 启动、示例文本分析、摘要生成、关键词、分点摘要、LiteRT 展示、Agent 问答、知识卡片、复习题和历史记录恢复。测试环境包括 Android 模拟器和安卓真机。

当前 V1.0 没有发现影响课堂展示的阻塞性问题。APK 是课程演示用 debug 包，不是应用商店发布版本。

### 第 15 页 总结与后续优化

总体来说，SmartRead Agent V1.0 已经完成了从文本输入、摘要分析、LiteRT 端侧推理、Agent 问答、知识卡片、复习题到历史记录的闭环。

不足也比较明确：摘要和 Agent 目前还是轻量规则方案，模型训练数据规模有限，历史记录也还可以升级为数据库。后续可以考虑增加 OCR 导入、扩充训练数据，或者在本地功能稳定的基础上增加可选的云端增强能力。

## 三、PPT 后 App 视频展示顺序

PPT 第 16 页结束后再播放视频，不在 PPT 中途切换。视频内容按以下顺序展示即可：

1. 打开 SmartRead Agent 首页，停留约 2 秒。
2. 选择示例文本。
3. 点击开始智能分析。
4. 展示一句话总结、关键词和分点摘要。
5. 停留 LiteRT 端侧分析区域，能看到句子重要性结果即可。
6. 进入 Agent 问答页，点击一个快捷问题。
7. 进入知识卡片和复习题页面。
8. 进入历史记录页面，恢复一条历史分析。
9. 回到首页或结果页，视频结束。

- 分工：林立洲负责核心开发和汇报，江轩宇负责真机体验、流程复核和视频展示。
