# SmartRead Agent 答辩可能问题

## 1. 这个项目解决什么问题？

SmartRead Agent 主要解决学生阅读课程资料、教材片段和文章时理解成本高、整理复习材料耗时的问题。用户可以把文本粘贴到 App 中，快速获得摘要、关键词、分点摘要、问答、知识卡片和复习题。

## 2. 为什么选择阅读摘要方向？

阅读和复习是学生日常高频场景，适合移动端使用，也容易在期末演示中形成完整流程。摘要、关键词、问答和复习题之间有自然关联，能体现 AI 阅读辅助的价值。

## 3. Agent 问答是怎么实现的？

V1.0 的 Agent 问答采用本地规则型实现，会读取当前文章的一句话总结、关键词和分点摘要，再根据用户问题生成围绕文章内容的回答。它不调用云端大模型 API。

## 4. LiteRT 模型起什么作用？

LiteRT 模型用于端侧句子重要性分析。App 会从文章句子中提取长度、关键词重合度、位置等特征，交给本地模型评分，并在摘要结果页展示重要性等级和推理来源。

## 5. 为什么不用云端大模型？

期末演示版本优先保证稳定性和可复现性。云端 API 需要网络、Key 和费用管理，也可能受到接口限流影响。V1.0 先保证离线可运行，把云端增强作为后续方向。

## 6. 端侧推理有什么好处？

端侧推理不依赖网络，响应更稳定，也不会把文本上传到服务器。对于课程项目来说，它能体现移动端 AI 实践和模型随 APK 分发的能力。

## 7. 模型输入是什么？

当前句子重要性模型输入是 5 个数值特征：句子长度、关键词重合度、句子位置、标点提示和总结提示词。输出是句子重要性得分。

## 8. 历史记录如何保存？

V1.0 使用 SharedPreferences 保存最近 12 条历史分析记录，包括原文、摘要、关键词、句子数、字符数和保存时间。该方式适合小规模课程演示。

## 9. 项目的创新点是什么？

项目把移动端阅读、摘要、端侧 AI、文章问答、知识卡片、复习题和历史记录整合到同一个 App 中，不只停留在单一文本摘要功能。

## 10. 项目最大的困难是什么？

一方面是小组人数少，核心开发和文档推进集中在项目负责人身上；另一方面是 LiteRT/TFLite 模型导出和 Android 集成需要同时处理模型文件、依赖和页面展示。

## 11. 你们小组如何分工？

本人担任项目负责人和核心开发，负责 Android/Kotlin 开发、AI 功能设计、LiteRT 集成、版本管理和文档推进。另一位成员主要参与需求反馈、功能体验测试、UI 建议、文档校对和演示配合。

## 12. 项目管理平台怎么使用？

项目使用 Leangoo 看板记录任务状态，把任务分为待规划、待开发、开发中、待测试、Bug 修复和已完成。每个阶段结束后整理截图作为课程过程材料。

## 13. Gitee 提交记录体现了什么？

Gitee 提交记录体现项目从 V0.1 立项、V0.2 摘要 MVP、V0.3 Agent 与知识卡片、V0.4 LiteRT、V0.5 历史记录到 V1.0 稳定版的迭代过程。

## 14. 当前项目不足是什么？

摘要和 Agent 问答仍是轻量本地规则方案，复杂长文效果有限；LiteRT 模型训练数据规模较小；历史记录使用 SharedPreferences，适合演示但不适合大量数据。

## 15. 后续如何优化？

后续可以扩充模型训练数据，优化摘要算法和 LiteRT 模型效果；把历史记录升级为 Room 数据库；在确保安全和稳定的前提下接入可选云端大模型增强问答能力。

## 16. 为什么说这是双课程共同项目？

软件开发实践（三）关注 Android App、源码、APK、演示和技术文档；软件项目管理关注版本管理、任务看板、沟通记录、测试 Bug 和个人管理报告。两个课程围绕同一个真实项目形成不同侧重点的交付。
