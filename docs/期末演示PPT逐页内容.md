## 2. 选题背景：学生阅读资料时，真正耗时的是“整理重点”

副标题：从阅读材料到复习材料，需要一个轻量移动端工具

- 课堂资料、教材片段、技术文章信息密度高，第一次阅读很难快速抓住主线。
- 手工整理摘要、关键词、复习题耗时长，而且容易遗漏重点。
- 手机是学生最容易随手使用的设备，适合承载轻量阅读辅助流程。

评分对应：APP 应用创新和实用性。

---

## 3. 项目目标：把阅读理解变成一个闭环

副标题：输入文本 → 提取重点 → 端侧分析 → 问答复习 → 历史回看

- 输入：粘贴文本或选择示例文本。
- 理解：生成一句话总结、关键词、分点摘要。
- 端侧 AI：使用 LiteRT 本地模型进行句子重要性评分。
- 复习：通过 Agent 问答、知识卡片和复习题整理学习材料。
- 回看：保存历史记录，支持恢复历史分析。

## 6. 技术架构

副标题：Android 本地分析为主，模型文件随 APK 集成

- UI 层：Jetpack Compose 组织首页、结果页、Agent、知识卡片、历史记录。
- 文本分析层：TextAnalyzer 完成分句、摘要、关键词、分点摘要。
- 智能交互层：LocalReadingAgent 完成本地规则型问答。
- 端侧模型层：SentenceImportanceClassifier 加载 `.tflite` 模型进行推理。
- 存储层：HistoryRepository 使用 SharedPreferences 保存最近记录。

---

## 7. 机器学习整合：LiteRT 端侧句子重要性分析

副标题：这是本项目移动机器学习整合的重点

- 模型目标：判断文章句子的重要性，辅助用户识别重点句。
- 输入特征：句子长度、关键词重合度、句子位置、标点提示、总结提示词。
- 模型文件：`sentence_importance_model.tflite`。
- 集成方式：模型放入 Android assets，App 运行时由 TensorFlow Lite Interpreter 加载。
- 输出结果：0 到 1 的重要性分数，并转为高 / 中 / 低等级展示。

评分对应：机器学习在应用中的整合程度，占比最高，应重点讲。

---

## 8. LiteRT 为什么有意义

副标题：不是只写模型文件，而是在 App 里完成端侧推理展示

- 离线可用：不依赖网络环境，适合课堂现场演示。
- 隐私更好：文章内容不需要上传服务器。
- 可解释：输入特征和输出分数都能向老师说明。
- 可落地：APK 内包含模型文件，Android 端真实加载并显示推理结果。
- 有兜底：模型加载失败时使用规则评分，保证演示不中断。

## 9. Agent 问答设计

副标题：本项目是本地规则型阅读 Agent，不调用 GPT API

必须口径：
- 当前版本没有调用 GPT API，也没有依赖云端大模型。
- Agent 基于当前文章的一句话总结、关键词、分点摘要和复习题规则工作。
- 通过问题意图识别判断用户要“概括”“关键词”“复习重点”“复习题”还是“知识卡片”。
- 优点是离线、稳定、可解释、可复现，适合课程演示。

如果老师追问：它不是通用聊天机器人，而是面向阅读辅助任务的轻量 Agent。

## 10. 学习材料生成

副标题：把阅读结果转化为可以复习的材料

- 知识卡片：由关键词、核心观点、分点摘要生成。
- 复习题：根据摘要和关键词生成简答题与参考答案。
- Agent 快捷问题：帮助用户快速查看文章主旨、关键词、复习重点。
- 历史记录：保存最近分析，支持回看和恢复。

演示重点：展示“从文章到复习资料”的闭环。

---

## 11. 核心数据对象

副标题：主要功能都有明确的数据结构承载

- ArticleAnalysis：原文、摘要、关键词、分点摘要、句子重要性结果。
- SentenceImportance：句子、分数、等级、推理来源。
- ChatMessage：用户问题与 Agent 回答。
- KnowledgeCard / QuizQuestion：知识卡片与复习题。
- HistoryRecord：标题、预览、保存时间、原文与摘要信息。
