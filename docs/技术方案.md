# SmartRead Agent 技术方案

## 总体架构

SmartRead Agent 采用移动端为主的轻量架构。Android App 负责文本输入、结果展示、本地摘要、关键词提取、历史记录和端侧模型推理。后续如时间允许，再接入云端 Agent，用于更自然的问答和知识卡片生成。

总体技术路线为：

Android/Kotlin + Jetpack Compose + 本地文本处理算法 + LiteRT 端侧模型 + 可选云端 Agent 增强。

## Android/Kotlin 技术路线

- 使用 Kotlin 作为主要开发语言。
- 使用 Jetpack Compose 构建页面。
- 采用简单清晰的页面结构，优先保证演示稳定性。
- MVP 阶段先实现单机可运行功能，减少网络依赖。
- 后续根据需要加入 ViewModel、Room 或 DataStore。

## 本地摘要算法思路

MVP 阶段先采用可解释的本地文本处理方法，不直接依赖复杂模型：

- 按标点切分句子。
- 统计词频或关键短语。
- 根据句子长度、关键词覆盖情况和位置给句子打分。
- 选取得分较高的句子组成分点摘要。
- 生成一句话总结时优先选取代表性最高的句子，并做长度控制。

该方案实现简单，便于调试，也能在离线环境下完成基本演示。

## Agent 问答实现思路

V0.3 已实现本地规则型 Agent 问答。用户当前文本、摘要和关键词作为上下文，问题作为输入，App 在本地生成摘要解释、复习重点、关键词说明和题目建议。后续如需要更自然的长文本自由问答，可接入可选云端接口，但当前版本不依赖网络。

当前阶段不写入 API Key，也不提交任何密钥文件。

## LiteRT 模型集成计划

V0.4 已训练轻量句子重要性模型，并导出 `.tflite` 文件。移动端通过 LiteRT 加载模型，对文章句子进行重要性评分。模型输出展示在摘要结果页，可作为端侧 AI 演示截图。

当前模型输入为 5 个数值特征：句子长度、关键词重合度、句子位置、标点提示和总结提示词。受限于本机 TensorFlow 安装环境，训练脚本优先支持 TensorFlow/Keras 训练与 TFLiteConverter 导出；本机实际执行时采用 NumPy 训练权重，并通过 TensorFlow Lite schema 与 FlatBuffers Java runtime 导出真实 `.tflite` 文件。

## 数据存储方案

- 当前输入和结果使用 Compose 状态保存，便于页面间切换。
- V0.5 已使用 SharedPreferences 保存最近 12 条历史记录，包括原文、摘要、关键词、句子数、字符数和保存时间。
- 不保存敏感信息。
- 测试数据以公开课程样例或自写短文本为主。

## 页面设计方案

计划页面包括：

- 首页：展示项目名称、文本输入入口和示例文本入口。
- 文本导入页：支持粘贴文本和选择示例文本。
- 摘要结果页：展示一句话总结、关键词和分点摘要。
- Agent 问答页：展示上下文问答。
- 知识卡片页：展示概念卡片。
- 历史记录页：展示历史分析记录。
- LiteRT 分析区域：在摘要结果页展示句子重要性分析结果。

## 离线兜底方案

- 摘要和关键词提取优先提供本地算法。
- 云端 Agent 不可用时提示用户当前为离线模式。
- 演示前准备示例文本和本地结果，降低网络风险。

## 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| Android 环境构建失败 | 影响 App 开发 | 优先创建最小可运行 Demo，记录环境问题 |
| Gradle 下载慢 | 影响搭建进度 | 使用稳定网络或镜像源，保留构建截图 |
| LiteRT 集成难度较高 | 影响 AI 亮点 | 已完成轻量模型和端侧推理接入，后续继续优化模型质量 |
| 云端 Agent API 不稳定 | 影响现场演示 | 提供离线摘要和关键词兜底 |
| 文档整理滞后 | 影响项目管理课程提交 | 每个阶段结束及时补充截图和记录 |
